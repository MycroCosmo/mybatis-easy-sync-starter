# MyBatis Easy Sync Starter

English · [한국어](README.md)

A Java 17 library that removes repetitive CRUD work in MyBatis and helps catch Mapper/XML mismatches. The goal is to keep the SQL you write by hand and automate only the boilerplate.

## Modules

| Module | Role |
| --- | --- |
| `mybatis-easy-core` | Merges basic CRUD SQL at runtime, field/column mapping, development-time entity generator |
| `mybatis-easy-processor` | Compile-time comparison of Mapper methods and XML statement IDs, optional stub generation |

Runtime SQL merging and compile-time validation are separate features. Stubs generated by the processor are not finished business SQL.

## Installation (local Maven repository)

Requires JDK 17 and the Gradle wrapper in this repository. Both modules are released with the same version (`1.0.3`). The steps below do not assume the artifacts are published to a public repository.

In this repository:

```bash
./gradlew :mybatis-easy-core:publishToMavenLocal :mybatis-easy-processor:publishToMavenLocal
```

On Windows use `.\gradlew.bat` instead of `./gradlew`.

In the consuming Spring Boot project's `build.gradle`:

```groovy
repositories {
    mavenLocal()
    mavenCentral()
}

dependencies {
    implementation 'com.thenoah.dev:mybatis-easy-core:1.0.3'
    // only if you want compile-time Mapper/XML validation
    annotationProcessor 'com.thenoah.dev:mybatis-easy-processor:1.0.3'
    runtimeOnly 'org.postgresql:postgresql'
}
```

The consuming project is expected to use Spring Boot 3.x and Java 17, plus the JDBC driver and DataSource configuration of your database.

## Requirements for enabling AutoSQL

**Extending `BaseMapper` alone is not enough.** The auto-configuration is created only when `mybatis-easy.autosql.enabled=true`, and the merge is skipped if no readable Mapper XML resource exists.

`application.yml` of the consuming project:

```yaml
spring:
  datasource:
    url: ${DB_URL}
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}

mybatis:
  mapper-locations: classpath*:mapper/**/*.xml

mybatis-easy:
  autosql:
    enabled: true
  generator:
    enabled: false
    allow-write: false
```

With the generator disabled, neither Java sources nor tables are created for you; prepare entities and tables yourself.

### Entity and Mapper example

```java
@Table(name = "users")
public class User {
    @Id
    @Column(name = "user_id")
    private Long id;
    private String name;
    // getters / setters
}

@Mapper
public interface UserMapper extends BaseMapper<User, Long> {
}
```

### Required XML resource

Path: `src/main/resources/mapper/UserMapper.xml`

```xml
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "https://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.example.demo.UserMapper">
</mapper>
```

The XML location follows `mybatis.mapper-locations`; if unset, `classpath*:mapper/**/*.xml` is used. The `namespace` must match the fully qualified Mapper class name. The auto-configuration finds the XML, links it to `BaseMapper` and merges the needed SQL into a virtual resource. A statement you write in the XML takes precedence over the generated one with the same ID.

## Main settings

| Property | Default | Description |
| --- | --- | --- |
| `mybatis-easy.autosql.enabled` | `false` | Enable AutoSQL merging |
| `mybatis-easy.autosql.refresh-mode` | `NONE` | `UPDATE_MARKER_BLOCK` refreshes the marker block in the XML to match the current entity |
| `mybatis-easy.autosql.quote-identifiers` | `false` | Quote table/column identifiers according to the dialect |
| `mybatis-easy.autosql.generated-key.key-column` | `id` | Generated key column. Set it when the PK column is not `id` (e.g. `member_id`) |
| `mybatis-easy.autosql.generated-key.strategy` | `AUTO` | `JDBC` (useGeneratedKeys) / `NONE`. AUTO resolves to `NONE` on Oracle |
| `mybatis-easy.pagination.enabled` | `false` | `findPage` / `countAll` SQL is generated only when `true` |
| `mybatis-easy.pagination.dialect` | `AUTO` | Inferred from the DB product name. Set it explicitly if the DB is not reachable at startup |
| `mybatis-easy.pagination.find-all.policy` | `NONE` | `CAP` (apply a row limit) / `DISABLE` (do not generate `findAll`) |

`findById` and `deleteById` are bound through `@Param("id")`, so the entity's PK field does not have to be named `id`.

## API

```java
int insert(Object entity);
Optional<T> findById(ID id);
List<T> findAll();
List<T> findPage(long offset, int limit);
long countAll();
int update(Object entity);
int deleteById(ID id);
```

`insert` and `update` also accept DTOs; fields are re-keyed to the entity through `@Column` / naming strategy. For tables that can grow large, prefer paging over unbounded `findAll()`. With `@SoftDelete`, `deleteById` becomes an UPDATE and reads exclude deleted rows.

## Optional: compile-time Mapper/XML validation

The processor reports missing statements, orphan statements and method overloads that collide on XML IDs.

- XML files in sub-directories of `mes.xmlDir` are checked as well.
- Methods inherited from `BaseMapper` are provided by AutoSQL at runtime: they are not reported as missing, and defining them in XML is not reported as orphan.
- Methods declared by the Mapper or inherited from other interfaces need an XML statement. Methods using `@Select` and similar annotations are excluded.

```groovy
tasks.withType(JavaCompile).configureEach {
    options.compilerArgs += [
        '-Ames.xmlDir=src/main/resources/mapper',
        '-Ames.failOnMissing=true',
        '-Ames.failOnOrphan=false',
        '-Ames.generateMissing=false',
        '-Ames.debug=false'
    ]
}
```

Runtime AutoSQL generation and the processor's XML check run at different times. Generated stubs use a managed region and do not replace writing the real SQL.

## Development-time entity generator

The JDBC-metadata source generator modifies local files. The auto-configuration requires `generator.enabled`, `generator.allow-write` and a development-environment check. Keep it disabled in production, and review the Git diff before and after generation even locally.

## Database support

| Database | Status |
| --- | --- |
| H2 | Integration tests (real CRUD) pass |
| PostgreSQL, MySQL, MariaDB, SQL Server, Oracle, SQLite | Dialect-specific SQL strings are unit-tested. **Not verified against a real database**; check in your own project before adopting |

## Scope of verification

```bash
./gradlew test
```

Test results are not the same as compile and DB CRUD results in your own project. This README describes the conditions for installation and activation and does not guarantee compatibility with every database and Spring Boot combination. This is not an ORM with a persistence context or entity lifecycle like JPA.
